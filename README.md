## Overview

DocuPilot AI is a document intelligence web application for securely processing private documents, extracting and reviewing invoice information, and finding answers backed by citations to original document pages. The frontend runs on **React + Vite** and the API uses **Django REST Framework**. **SQLite3 is the only application database**; Celery and Redis are optional for background extraction.

## Live Demo

**Application URL:** `https://docu-pilot-ai.vercel.app/`


## Features

- **Private document management:** Owner-scoped uploads, listings, extraction, deletion, and authorized source-PDF access.
- **PDF, image and text extraction:** PyMuPDF for PDF text, UTF-8 TXT, and optional Tesseract OCR for scanned documents and supported images.
- **Evidence-grounded Q&A:** Keyword, optional local multilingual semantic, and hybrid retrieval with page-linked source excerpts. Answers are extractive, not generated by an external LLM.
- **Invoice intelligence:** Invoice fields and line items, arithmetic checks, payment statuses, human review, supplier analytics, dashboards, and CSV export.
- **Explainable classification:** Invoice, policy, report, contract, or unknown, with page-level matching evidence and human verification/override history.
- **Quality reporting:** Synthetic classifier evaluation, optional independently adjudicated offline evaluation, and owner-scoped operational feedback reports.
- **Optional background jobs:** Celery + Redis extraction with job tracking and operator-controlled recovery.
- **Security and recovery:** CSRF-protected Django sessions, login rate limiting, idle expiry, access-control tests, and verified SQLite3/private-media backup and restore.

## Getting Started (Windows 11)

Prerequisites: Python 3.12, Node.js, npm, and PowerShell. Install Tesseract OCR separately to use OCR features.

**Backend — PowerShell terminal 1** (from repository root):

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend/requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
cd backend
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

**Frontend — PowerShell terminal 2** (from repository root):

```powershell
cd frontend
npm install
npm run dev
```

Open **http://127.0.0.1:5173** to use the local app. The frontend proxies `/api` to Django in local development. Set a unique `DJANGO_SECRET_KEY` and production HTTPS configuration before any external deployment. Optional dependencies are provided in `backend/requirements-semantic.txt` and `backend/requirements-async.txt`.

## Testing

```powershell
# In backend/, with the Python virtual environment activated
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test --verbosity 2
python manage.py release_acceptance

# In frontend/
npm test
npm run build
npm run test:e2e

# From repository root
python -m unittest discover -s scripts -p "test_*.py" -v
```

Playwright is configured for an installed Google Chrome browser. The synthetic evaluation fixtures are not independent evidence of real-world classification accuracy. Full public deployment requires separate security and infrastructure acceptance.

## Deployment

The backend can be deployed to Render and the frontend to Vercel from the
repository root. Create the Render web service from
[render.yaml](render.yaml), or set these backend environment variables
manually:

- `DJANGO_DEBUG=false`
- `DJANGO_SECRET_KEY` to a unique random value of at least 50 characters
- `DJANGO_ALLOWED_HOSTS` to the Render hostname, without `https://`
- `DATABASE_URL` to the Render PostgreSQL connection string. In Render, use
  **Add from database** to link the database instead of copying the password
  into source control.
- `DOCUPILOT_FRONTEND_ORIGINS` to the exact Vercel origin, for example
  `https://your-app.vercel.app`
- `DJANGO_CSRF_TRUSTED_ORIGINS` to the same exact Vercel origin
- `DJANGO_TRUST_PROXY_HTTPS=true`
- `DJANGO_SESSION_COOKIE_SAMESITE=None`
- `DJANGO_CSRF_COOKIE_SAMESITE=None`

Set `VITE_API_URL` in the Vercel project to the Render backend origin, for
example `https://docupilot-api.onrender.com`, then redeploy the frontend.
The frontend sends credentialed requests to the backend and the backend
allows only the configured Vercel origin. Do not use a trailing slash in
`VITE_API_URL`.

Render's default filesystem is ephemeral. The PostgreSQL database persists
structured data, but uploaded files in `backend/private_media/` do not survive
service restarts or redeploys without a persistent disk or external object
storage. Configure durable private file storage before relying on uploads in
production.

## Backup and Recovery

```powershell
# From repository root, after creating the backups directory
python scripts/backup_restore.py backup --archive backups/docupilot.backup.zip
python scripts/backup_restore.py verify --archive backups/docupilot.backup.zip
python scripts/backup_restore.py restore --archive backups/docupilot.backup.zip
```

Restore is a **dry run by default**. A real restore requires stopping Django/Celery and explicit confirmation, and must be performed in an empty data location. Backup archives contain private files and are not encrypted by the utility.
